# テストの書き方（定数・判定条件を本当に守るために）

このファイルは 2026-09-26 に `AGENTS.md` から中身をそのまま移したもの。`monitor.yml` の pytest 対象外の分岐を手で通す手順は `state-design.md` の「state の永続化は monitor.yml とセット」にある。

### ★ 定数とフォールバック値は「値そのもの」を書いたテストで守る

2026-09-10 の mutation testing で、**通っているのに何も守っていないテスト**が5件出た。
通常のレビューでは4周やっても誰も気づかなかった。

```
   ✗ 境界テストに兼ねさせる                ○ 値そのものを別に固定する
   ─────────────────────────────────     ─────────────────────────────
   state = now + TOLERANCE + 1           assert TOLERANCE == 60
   → 引き直されること                     ← 定数を変えたらここが落ちる
   ＝ 定数を変えると期待値も一緒に動く
     ので、60→300 にしても落ちない
```

同じ形で抜けていたもの:

| 守れていなかった対象 | 抜けの形 |
|---|---|
| `FUTURE_TS_TOLERANCE_SEC` / `MAX_CATCHUP_SEC` | 境界テストが定数をその場で参照している |
| `broken` 欠落時の `"(不明)"` | 値が必ず入っている形しか通していない |
| `also_broken` の蓄積 | 2回目までしか通しておらず、3回目以降が未検証 |
| `【契約獲得】` と `リピッテホテル` の and 条件 | 正常系だけで、**弾く側**のテストが無かった |

**★ 判定条件は「通す側」と「弾く側」を両方書く。**
最後の1件は、条件を片方だけに変えても全テストが通る状態だった
（＝「リピッテホテル」という語を含むだけの雑談を転記しうる回帰を検知できない）。
