# 下流（cnctor-onboarding）への目印と、元スレッドへの完了報告

このファイルは 2026-09-26 に `AGENTS.md` から中身をそのまま移したもの。転記文の目印と完了報告の文面を変えるときに読む。

### ★ 下流に渡す目印を URL の形にしない

**2026-09-10 に Gemini Pro と GPT-5.6 Sol が独立に同じ指摘を出した。**

```
   Slack は conversations.history で本文を返すとき、
   自動リンク化した URL を <https://...> の形（mrkdwn）に変えて返す
        ▼
   生URL前提の正規表現は **本番でだけ** 外れる
        ▼
   完了報告が #job_sales の元スレッドへ戻らず、転記先のスレッドに出る
        ▼
   テストは生文字列を渡すので、最後まで気づけない
```

だから転記文には**2つ別々に**添える。役割が違うので片方に兼ねさせない。

| | 何のためか | 出る条件 |
|---|---|---|
| `（元の投稿: https://...）` | **人**が元投稿へ飛ぶための表示物 | `SLACK_WORKSPACE` があるとき |
| `元投稿ID: <channel>/<ts>` | **機械**（cnctor-onboarding）が元スレッドを復元する | **常に** |

- **目印から山括弧・`://` を出さない。** Slack の整形で変わらない形に保つ
- **ts を「秒10桁＋小数6桁」と決め打ちして復元しない。** 生の ts をそのまま渡す
  （桁数の仮定は Gemini Pro の指摘。パーマリンク形式から復元する実装は捨てた）
- 受け側（[[cnctor-onboarding]] の `core.report_target`）は、目印が指す先が
  **#job_sales でなければ捨てる**。本文は営業の自由文で、過去の転記をコピーして
  貼ることがある。書かれたチャンネルIDを信じると無関係な場所へ報告を投げる

### 完了報告は #job_sales の元スレッドへ（2026-09-10 本人指示）

**「完了してもしなくても、できたこと／できなかったこと／残っているタスクを報告する」。**

- 報告先は**常に #job_sales の契約報告の元スレッド**。転記先に出しても報告者と営業部は見ない
- 残りは「〜については、〜さんよろしくお願いします！」の形。**語尾は「!」**
- **相手が決まらない残タスクは行ごと出さない。** `<@>` は通知が飛ばないただの文字列で、
  誰宛か分からない依頼は全員が自分以外の仕事だと思う
- **「事業計画の反映」はこちらでは出さない。** リピッテホテルは転記のあとに
  [[cnctor-onboarding]] が同じ元スレッドへ報告する。両方が積むと同じ人に同じ依頼が2回届く
- **添付の失敗と、完了報告の失敗を同じ except でまとめない。**
  まとめると、添付は全部転送できているのに「添付が失敗」と伝えることになり、
  読んだ人が同じファイルをもう一度貼る
