# Actions のログの見分け方（人が読むとき）

このファイルは 2026-09-26 に `AGENTS.md` から中身をそのまま移したもの。`#repitte-hotel` に同じ報告が繰り返し並ぶときの見方は `state-design.md` の「一度きりの事故ではない」も併せて読む。

### ログの見分け方（Actions のログを人が読むとき）

| 表記 | 意味 | 対処 |
|---|---|---|
| `[DONE]` | 何件取得して何件転記したか。**正常な回にも必ず出る** | 不要 |
| `[EMPTY]` | 新着0件。stateは据え置き | 不要 |
| `[INIT]`（初回） | stateがまだ無いので起点を決めた | 不要 |
| `[REPAIR] ★stateが壊れていた` | **これがいちばん重要。** stateを引き直した。壊れていた間の契約報告を取りこぼしているおそれがある | **要確認** |
| `[REPAIR] 前回言えなかった…` | 届かなかったお知らせを言い直せた | 不要 |
| `[WARN]` | 自動で直して続行した（stateの巻き戻り拒否など） | 原則不要。続くなら要確認 |
| `[ERROR]` | 転記・添付・お知らせの送信が失敗した | **要対処** |

**★ `[WARN]` の直後の `[REPAIR]` を読み飛ばさない。**
stateが壊れていた回は、まず `_read_state_raw()` が `[WARN]`（表では「原則不要」）を出し、
そのすぐ後に `[REPAIR] ★` が続く。`[WARN]` を見て「不要」と読み飛ばすと、
**本当に見るべき行を素通りする**（2026-09-10 の obasan-quality 指摘）。

```
   [WARN] stateが未来の時刻を指しているため起点を引き直します（…）   ← 原因
   [REPAIR] ★stateが壊れていたので起点を … に引き直しました（…）    ← ★こちらが本体
```
